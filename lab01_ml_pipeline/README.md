# Лабораторная №1: ML pipeline

Решены все три части задания из ветки `23f_basic` курса girafe-ai. Исходные файлы и их контрольные суммы описаны в [SOURCE.md](SOURCE.md).

## Состав решения

- [Часть 1 — производные и kNN](lab01_part1_questions.ipynb): выводы всех градиентов, правило цепочки с явным соглашением о vec, численная проверка, ответы на три вопроса kNN. [Текстовая версия](lab01_part1_questions.md).
- [Часть 2 — ML pipeline](lab01_part2_ml_pipeline.ipynb): предобработка, LR/CV, accuracy и macro-F1, ROC для четырёх классов, PCA, дерево, bootstrap-бэггинг LR/деревьев, случайный лес, learning curve из десяти частей, нативный XGBoost. [Текстовая версия](lab01_part2_ml_pipeline.md).
- [Часть 3 — SVM и ядра](lab01_part3_svm_kernels.ipynb): линейные модели, poly/RBF/sigmoid, явные полиномиальные признаки; moons, circles и объединённая четырёхклассовая задача. Включены области решений, таблицы и письменные выводы. [Текстовая версия](lab01_part3_svm_kernels.md).

Ноутбуки — сдаваемые файлы с сохранёнными результатами и графиками. Markdown-файлы содержат те же исходные ячейки без объёмных outputs; численные итоги также включены в письменные выводы. После правок ноутбуков текстовые копии обновляет `run_notebooks.py`.

## Воспроизведение

Проверено на Python 3.13. Зависимости зафиксированы в `requirements-lock.txt`. scikit-learn 1.6.1 выбран намеренно: он поддерживает явный `multi_class='multinomial'`, требуемый условием. SciPy 1.15.3 согласована с этой версией sklearn. Для XGBoost на macOS при отсутствии OpenMP может понадобиться системная библиотека `libomp`.

Из корня репозитория:

```bash
python3.13 -m venv /tmp/ml-lab01-env
source /tmp/ml-lab01-env/bin/activate
python -m pip install -r lab01_ml_pipeline/requirements-lock.txt
python -m ipykernel install --sys-prefix --name python3
python lab01_ml_pipeline/run_notebooks.py
```

Скрипт запускает каждый ноутбук в отдельном чистом ядре, с рабочим каталогом самой лабораторной, проверяет формат и сохраняет результаты. Фиксированный seed — 42, вычисления моделей идут в одном потоке.

Для повторения в том же окружении с проверкой совпадения текстовых outputs и PNG:

```bash
python lab01_ml_pipeline/run_notebooks.py --check-reproducibility
```

Сравнение игнорирует время исполнения и служебные HTML ID. В другом окружении численные библиотеки и шрифты могут дать небольшие различия; идентичность PNG между разными ОС не обещается.

## Результаты проверки

Все три ноутбука выполнены последовательно, ошибок ячеек и предупреждений о несходимости нет. Проверены численные производные и соглашение о векторизации. В части 2 сохранены 8 рисунков, в части 3 — ещё 8; графики просмотрены визуально. Повторный запуск в том же окружении проверяет совпадение outputs. Зависимости прошли `pip check`.

На Vehicle: 846 объектов, 18 признаков, train/test — 549/297. Первый столбец CSV является индексом строки и исключён из признаков. Пропусков и полных дубликатов строк нет.

| Модель | Test accuracy | Test macro-F1 |
|---|---:|---:|
| LR | 0.8350 | 0.8344 |
| PCA + LR, 7 компонент | 0.6195 | 0.6153 |
| Дерево, глубина 7 | 0.7205 | 0.7171 |
| Бэггинг LR, 17 моделей | 0.8350 | 0.8346 |

На moons accuracy линейных моделей — 0.8533, RBF-SVM и полиномиальной LR — 0.9867. На circles полиномиальная LR степени 2 даёт 0.9267 против примерно 0.5 у линейных моделей. На объединённой задаче RBF-SVM даёт 0.9333, LR со степенью 4 — 0.9233.

## Разделение данных и ограничения выводов

Train/test-разбиения фиксированы и стратифицированы. Scaler, PCA и генерация/масштабирование полиномиальных признаков обучаются внутри CV Pipeline. Число моделей в бэггинге и лесу выбирается по train OOB с покрытием не менее 99%; число итераций бустинга — через train-CV. Test используется для требуемых итоговых оценок и графиков; параметры после просмотра test не подстраивались.

OOB после выбора C/глубины на всём train не является независимой оценкой всей процедуры поиска. Learning curve использует уже выбранные параметры: она описывает фиксированные модели при разном объёме данных, а не полную процедуру подбора на каждой малой части. Test многократно показан на требуемых кривых; выбор лучшей конфигурации по этим кривым потребовал бы нового независимого теста.

Эксперименты выполнены для одного seed и небольших сеток. Разница в несколько правильных ответов не доказывает устойчивое превосходство. Сохранение дисперсии PCA не гарантирует сохранения классовой информации.
